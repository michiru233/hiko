## 调研：Hiko 接入 Kikoeru 在线服务器（asmr.one）可行性

用户要求参考 https://github.com/pa-jesusf/KikoFlu 让 Hiko 支持在线服务。**结论：完全可行，成本低于预期。**

### 实测得到的 asmr.one API 契约（2026-09-25 验证）
主机：`api.asmr.one` / `api.asmr-200.com` / `api.asmr-100.com` / `api.asmr-300.com`（四个镜像 `/api/health` 均 200）。
`www.asmr.one` 是 Web 前端。CDN 是 Cloudflare + Backblaze B2（`raw.kiko-play-niptan.one`）。

| 端点 | 匿名可用 | 说明 |
|---|---|---|
| `GET /api/works?page&pageSize&order&sort` | ✅ 200 | 返回 `{works, pagination{currentPage,pageSize,totalCount}}`，全站 62453 件 |
| `GET /api/work/{id}?v=2` | ✅ 200 | 详情。注意是**单数** `work` |
| `GET /api/tracks/{id}` | ✅ 200 | 曲目树，含 `hash` / `mediaStreamUrl` / `size` / `type`。**单数端点是公开的** |
| `GET /api/search/{keyword}` | ✅ 200 | 关键词搜索，带 pagination |
| `GET /api/cover/{id}` | ✅ 200 | 直接返回 JPEG |
| `GET /api/media/stream/{hash}` | ✅ 302 | hash 形如 `1657200/1937305`；302 到带 `?verify=<10小时有效期签名>` 的 CDN 直链 |
| `mediaStreamUrl` 字段 | ✅ | **裸 CDN 直链**，无签名也返回 206，Range 支持良好（`content-range`） |
| 字幕串流 | ✅ 200 | 作品自带 LRC/VTT，UTF-8(BOM)，可直接喂现有歌词系统 |
| `/api/auth/me` POST | — | 登录 `{name,password}` → `{token}`；GET 返回 `{"user":{"loggedIn":false},"auth":true,"reg":true}` |
| `/api/auth/reg` POST | — | 注册 `{name,password,recommenderUuid}` |
| 旧端点 `/api/works/{id}`、`/api/works/{id}/tracks` | ❌ 401 | 需要 token，**不要用** |
| `/api/tags` `/api/review` `/api/playlist` `/api/favourites` `/api/progress/{workId}` | ❌ 401 | 需登录 |

**关键结论：浏览 + 在线流播完全不需要账号。** token 走 `?token=` query 参数（也支持 `Authorization: Bearer`）。
KikoFlu 会为官方服务器伪装浏览器 UA + `Referer: https://www.asmr.one/`，但实测**不伪装也能通**。

### KikoFlu 侧事实
- 技术栈 Flutter + dio + just_audio + media_kit，**GPL-3.0**（不能抄代码，只可借鉴 API 契约）。
- 有完整代理层：`ProxyMode {direct, system, manual}` + 全局 `HttpOverrides`，内网地址强制直连。
- 音频缓存：自定义 `CachingStreamAudioSource extends StreamAudioSource`，手写 Range 请求 + 边播边写缓存文件，支持断点续传。

### Hiko 侧挂载点（已确认）
- `Track.url` 是字符串，`http(s)://` 天然可存；`lib/models/track.dart:5`。
- 播放唯一注入点 `lib/playback/playback_controller.dart:276` 的 `_player.setUrl(track.url)`。
- 桌面 `hiko_media_kit_player.dart:568` 已透传 headers（`Media(uri, httpHeaders:)`），但**用 query token 的话无需 header**。
- `cleanMissing`（桌面 `platform_service.dart:139-162`）会误删无本地文件的专辑 → 远程专辑必须按来源旁路。
- `CoverCache` 只吃 `data:` URL（`cover_cache.dart:41-50`），http 封面要走无缓存的 `Image.network`（`cover_art.dart:109`）→ 需新增 URL 缓存路径，否则 6 万作品滚不动。
- `filter.dart:19` 视图白名单：新增「在线」视图必须在这里加分支，否则会被当成分类名筛空。
- `settings_store.dart` 的 `scrapeProxy`（`:32/:148/:290`）是现成的字符串设置项范例，可复用做服务器地址。
- 无 `AudioSource.uri(headers:)` 调用；`pubspec` 已有 `http: ^1.6.0`，无 cookie/token 管理库。
- hiko/ 与仓库根**均无 LICENSE 文件**（默认 All Rights Reserved）。
- Android `INTERNET` 权限已有；https 不需要 cleartext 配置。

### 待验证（需账号或后续实测）

- 国内网络直连稳定性（本机实测 api.asmr.one 全部 200，延迟 ~0.7s）。

### 追加实测：筛选能力（全部匿名可用）
- `order` 支持：`create_date` / `release` / `dl_count` / `rate_average_2dp` / `review_count` / `price` / `random`
- `pageSize` 支持到 500+
- `/api/tags/`、`/api/vas/`、`/api/circles/` 全量列表可匿名拉取。
  **标签自带 i18n（zh-cn / ja-jp / en-us）**，可直接显示中文标签名。
- `/api/tags/{tagId}/works`、`/api/vas/{vaId}/works`、`/api/circles/{id}/works` 端点存在
  （注意 `vaId` 是 UUID，不是数字）。
- `/api/works?...&subtitle=1` 接受字幕筛选参数。
- `/api/recommender/popular` 在此实例上 404（不可用，别用）。

## ⚠️ 构建环境新坑：macOS 27 上 sandbox-exec 限制性 profile 失效

`flutter build macos` 报 `xcodebuild: error: Could not resolve package dependencies:
sandbox-exec: sandbox_apply: Operation not permitted`。

**根因（与代理、与我们的沙箱放行都无关）**：本机 macOS 27.0 + Xcode 27.0。
实测 `sandbox-exec -p '(version 1)(allow default)' true` 能过，但 `deny default` 的限制性 profile
一律 `Operation not permitted`（exit 71）——**该系统版本已不允许应用限制性 sandbox profile**。
xcodebuild 解析 SPM manifest 时正是套 `deny default` 那一套，于是必挂。

调用链（读 flutter_tools 源码确认）：迁移 → `XcodeProjectInterpreter.getInfo` →
`prefetchSwiftPackagesForProject` → `xcrun xcodebuild ... -resolvePackageDependencies`
（`ios/xcodeproj.dart:197` / `xcode_project.dart:403-447` **硬编码，没有开关可关**）。

**有效解法 —— 写 Xcode user defaults**（两个域都要写）：
```bash
for d in com.apple.dt.xcodebuild com.apple.dt.Xcode; do
  for k in IDEPackageSupportDisableManifestSandbox IDEPackageSupportDisablePluginExecutionSandbox IDEPackageSupportDisablePackageSandbox; do
    defaults write $d $k -bool YES
  done
done
```
写完 `flutter build macos --release` 直接通过。

**已排除的无效解法**（别再试）：
- `XCODE_XCCONFIG_FILE=...xcconfig` 注入同名键 —— 这两个键是命令行参数级，不是构建设置，无效
- `flutter build macos --config-only` —— 照样先跑迁移，同样失败
- 单独跑 `xcodebuild -resolvePackageDependencies -IDEPackageSupportDisableManifestSandbox=1` 能成功，
  但**不能**让后续 flutter 构建通过（flutter 会用不同 container / 缓存路径重新解析）

副作用：全局降低了 Xcode 解析 SPM manifest 的沙箱强度。还原用 `defaults delete <domain> <key>`。

## 发布 Hiko 1.91.0：在线界面完善（详情页对齐 / 目录树 / 分页）

**用户四项诉求**（macOS 端测试所得，Android 未实机验证）→ 三轮 grilling（Q1–Q15）全部裁决后实施。

### 本轮新增实测（修正 1.90.0 的漏项）
- **audio 节点有 `duration`**（浮点秒，如 `291.4832`）。1.90.0 的 `_flatten` 只取了 `size`，
  所以在线曲目行显示不出时长。**教训：不要凭部分字段输出下结论，要 dump 完整节点。**
- **folder 节点只有 `type` + `title`**，没有 count/duration —— asmr.one 网页的「2 项目, 36min」
  是前端自己聚合的，Hiko 也自己算（`OnlineFolderNode.audioCount / totalSeconds`）。
- 目录深度 0~3 层都有，**同一作品内深度会混**；顶层目录几乎总是「同内容的不同版本」
  （格式 / 语言 / 有无效果音），这是用户觉得「重复」的原因。
- `pageSize` 服务端支持到 500；全站 62453 件（20 条/页 = 3123 页）。
- **`https://api.asmr.one/works/{id}` = 404**，作品网页在 `www.asmr.one`（已做域名映射 `onlineWorkPageUrl`）。

### 关键实现决策
- 抽 **`lib/ui/widgets/detail_kit.dart`** 作为本地 `DetailDrawer` 与在线 `OnlineDetailPanel` 的共用视觉件。
  两处「要求一致」的界面各复制一份必然漂移，数值只留一个出处。`detail_drawer.dart` 699 → 386 行。
- 「当前播放行」用 **URL 反解 hash** 定位（`KikoeruClient.hashFromPlaybackUrl`），**不用数组下标** ——
  在线有「整部 / 单个目录 / 叶子目录」三种播放范围，下标互不对齐。
- 节点树**不重新构造 `OnlineTrack`**，按 hash 从拍平列表取回同一实例，保证字幕配对结果只有一份（单测用 `identical` 钉死）。
- `folderKeysIn` **只收 `audioCount > 0` 的目录**，否则「全部折叠」状态永远达不到。
- `OnlineDetailBody` 的 `State` 会被跨作品复用 → 两处调用点都挂 `key: ValueKey(workId)` 重置 Tab 与折叠态。
- 在线面板 σ55 氛围背板外套 `RepaintBoundary`（`OnlineCover` 自身还有一层 σ20，1.88.1 硬约束的延续）。
- 新增依赖 `url_launcher`（落地已批准的「在浏览器打开」）。

## 发布 Hiko 1.92.0：在线详情页目录默认全折叠 + 列表筛选改下拉菜单

**用户两项诉求**（macOS 端实测，Android 未实机验证）→ 两轮 grilling（Q1–Q11 + 一条追加）全部裁决后实施：
① 专辑详情页文件夹默认只展开一个、其余折叠；② 筛选改下拉菜单，形态仿 asmr.one 网页版。

### 本轮新增实测（asmr.one 接口）
- 排序 `order` 走白名单，**白名单外一律 400**；`rating` 在白名单里但**匿名返回 0 条**（要登录）→ 刻意不收。
- **`order=id` 对 RJ 作品数值上就等于 RJ 号**（`id=1657200` ↔ `RJ01657200`），BJ/VJ 在 `1000000xx` 段。
- `create_date` 与 `release` 的 desc 首页 8 条逐条相同，asc 才分叉。
- `/api/search/{kw}` 与 `/api/tags/{id}/works` **都支持全部排序键** —— 顺手**修掉 tags 端点写死 `sort=desc` 的既有 bug**。
- **`PopupMenuButton.constraints` 存在**，且菜单体本身是 `SingleChildScrollView` →
  给 `maxHeight` **自动获得滚动**，不用自己实现；菜单宽度由 `IntrinsicWidth(stepWidth)` 决定，
  条目内容包 `SizedBox(width: 168)` 才能让宽度可预期。

### 关键实现决策
- **`OnlineSource{browse,search,tag}` × `OnlineSort` 正交**：旧的 `OnlineFeed` 把「榜单」和排序搅在一起，
  于是「热门榜按价格排序」这种自相矛盾的状态在类型上都可表达；拆开后 chip 退化为**排序预设**
  （点了可再改排序，改了就两个 chip 都不高亮）。
- **方向写进条目名**（「销量倒序」而非「销量」+ 方向开关）→ 扁平静态菜单、无隐藏状态，便于照搬 asmr.one。
- `subtitleOnly` 与来源正交：`applyPreset` 不动它，`search` / `selectTag` 清它（避免「看不见的筛选」）。
- 详情页 `_collapsed` → **`_expanded`（初始空集 = 全折叠）**；自动展开只**增**不减，
  用 `_revealedHash` 去重 → 既不每帧重复触发，也不会把用户手动折回的目录强行再打开。
- 两跳 post-frame：build 里不能直接 setState → 排 post-frame → setState → 再排一个才 `ensureVisible`。
- `allExpanded` 判定用 `folderKeys.every(_expanded.contains)` 而不是比长度。

### 踩坑（写进了测试注释）
- widget 测试滚动断言首版 `pixels` 恒 0。**根因不是逻辑**：`AnimationController` 的 ticker
  **首帧只在打点（elapsed = 0）**，`ensureVisible(duration: 280ms)` 后要**两次 `pump(duration)`** 才见位移。
- `pathToHash` 第一版「先递归再检查 children」→ 深层命中丢了上层路径（只返 L3）；改成
  「先查本层 → 命中返 `[path]`，否则递归命中返 `[path, ...deeper]`」。
