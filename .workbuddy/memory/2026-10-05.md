## liquid_glass_widgets 评估（结论：部分可用，接入与否待裁决）

来源：用户看到 https://pub.dev/packages/liquid_glass_widgets 问「有没有哪些能用在项目里」。

**核过的事实**（pub.dev + GitHub main 的 `pubspec.yaml` / `README` + changelog）：
- v1.9.0（2026-10-05 当天发布），MIT，publisher `pixel-innovations.com`，
  仓库 `sdegenaar/liquid_glass_widgets`，约 282 likes / 160 points / 71.5k downloads。
- `environment: sdk ">=3.5.0 <4.0.0", flutter ">=3.41.0"` → Hiko（Flutter 3.47.0 / Dart 3.13.0）**满足**。
- `dependencies:` 只有 `flutter`，**零第三方运行时依赖**；自带 5 个 GLSL `.frag`
  （包内 `flutter: shaders:`），随包自动打包，**不需要改 Xcode / Gradle / CocoaPods**。
- `platforms:` android / ios / linux / macos / web / windows —— Hiko 三端全覆盖。
- **核心 pattern 是 `GlassScaffold` + `GlassAppBar` + `GlassTabBar`**（它想接管导航骨架），
  且 `initialize()` 要放在 `main()`、`LiquidGlassWidgets.wrap(child:, brightnessResolver:)` 要包住整个 app
  （`MaterialApp` 还要在 `builder` 里补一层 `Material(type: MaterialType.transparency)`）。
- **⚠️ 官方原文限制**：premium 档「Use Premium only for static, non-scrolling surfaces …
  It may not render correctly inside `ListView` or `CustomScrollView` on Impeller」
  → Hiko 的专辑网格 / 在线瀑布流恰好就是这一类。
- **⚠️ 平台档位分叉**：`GlassAdaptiveScope` 把 **Windows / Linux / Web 静态钉在 `GlassQuality.standard`**，
  只有 Metal(macOS) / Vulkan(Android) 走完整 16-shape 管线 → 与「三端一套皮肤」的既有决策冲突。
- 迭代极快：1.0.0 → 1.9.0 共 21 个版本（1.9.0 就在评估当天发的）；破坏性变更集中在 1.0.0，
  之后以行为变更 + 修复为主。
- 包自身的 golden 测试需要 Impeller → **玻璃观感在 `flutter_test` 里基本锁不住**，只能实机肉眼看。

**初步可用清单**：
- 值得看：`GlassMenu` + Liquid Morph（菜单从触发点"长出来"）—— Hiko 现在完全没有这种动效；
  `GlassCard` / `GlassContainer` 用于**固定不滚动**的面板；`GlassModalSheet`。
- 不建议换：胶囊系列（`HikoTagChip` / `OnlinePill` 已有独立字号旋钮 + 六类配色 + 可测纯函数）；
  桌面侧边栏（库里没有对应物）；卡片网格（官方限制）；底部导航（Hiko 是 `navViews` 配置驱动，语义不匹配）
  —— 这条待裁决。

### 上述评估的三处修正（当天接入实施时读源码后推翻）

1. **`GlassScaffold` / `GlassAppBar` 确实存在**（`lib/widgets/surfaces/glass_scaffold.dart:120`、
   `glass_app_bar.dart:89`），但**它们不是必需的**。查源码后确认：`wrap()` 注释明写 optional
   （只在用 `theme:` / `adaptiveQuality:` 时才需要）、`initialize()` 只是预热 shader、
   `GlassContainer(useOwnLayer: true)` 自带图层不需要祖先 → **连 app root 都不用改**。
2. **「卡片网格不能接」要按档位区分**：官方限制针对的是 **premium** 档。`standard` 档走
   `LightweightLiquidGlass`（包注释自称 "optimized for scrollable lists"、"5-10x faster than
   BackdropFilter"）→ **滚动列表可以接**。
   ⚠️ 但下面这半句当天就被推翻了：「~~且 `backgroundKey` 可选、不传就完全不逐卡捕获背景~~」
   —— `backgroundKey` 只管静止背景的采样 ticker，**真正的性能开关是 `blur`**：
   `blur > 0` 时 `paint()` 无条件 `pushLayer(BackdropFilterLayer)` 且 `alwaysNeedsCompositing`
   变 true。按这条错结论让 tile 档吃到默认 `blur = 20`，就是 1.99.23 修的移动端卡顿。
3. **面分布盘点有误**：先前把首页几处 `*GlassCard` token 当成「列表卡」，实际是静态工具栏胶囊；
   **在线卡根本没有玻璃**；滚动列表里唯一的玻璃卡只有专辑卡。

### 1.99.24 实施（深色模式卡边亮环 + 顶栏色差）— 详见 plan 文件同名章节

- 触发：用户实机（浅色已满意，**深色**仍不满意，mac + 移动一起看）
  「专辑卡边框显得不自然」+「最上面一层有色差」，附 3 张 873×1920 截图。
- 用 PIL 逐像素量化定位到**两个独立成因**，都不是调 token 能好的表层问题：
  - 卡边亮环 = 轻量着色器写死的结构白边。`uBackdropLuma` 在库里是**硬编码常量**
    `isDark ? 0.15 : 0.85`（`lightweight_liquid_glass.dart:454` / `glass_effect.dart:450`），
    深色 `rimFade = 1.0`、浅色 0.08。实测深色卡边缘峰值 168（卡内底色 31）、
    播放栏上边 166；浅色是同 token 却无亮峰（238→253 单调）。
    **`fresnelStrength` 够不到它**（只缩放另一项较小的加法项），一度以为能修，读源码后自我更正。
  - 顶栏色差 = 本页 `Stack` 首子项的「封面环境光晕」（σ80，深色 0.15，1.55.0 有意引入）
    只在顶栏透出来 —— 移动端内容头部从 1.99.9 起垫了页面底色，顶栏没垫。
    实测顶栏 (53,50,59) vs 全屏 (30,31,36)，还有横向左亮右暗渐变。
    底栏没有亮边是因为 `borderRadius: 0` 命中 `_isFlatEdge`。
