## 封面模糊根因（已修复 + 有回归锁）

`/api/cover/{id}.jpg?type=` 白名单**只有 `240x240` / `main` / `sam`**，其余 400。
`type=main` ≡ 不带参数 = **560×420**（md5 相同）；`type=sam` = 100×75；**服务端没有中间档**。

列表此前用 240×180 缩略图 —— 卡片宽 200~260 逻辑像素、Retina 需 400~520 物理像素，
`BoxFit.cover` 裁方后只剩 180×180 → **放大 2.4~2.9 倍**。详情页本来就走原图，所以只有列表糊。

修法：新增**单一出口 `coverMainUrl(workId)`**（`?type=main`），列表/详情/背板/播放器全走它。
`test/ui/online_work_card_test.dart` 用 `HttpOverrides` 拦真实请求，钉住 URL 里必须有 `type=main`。

## 账号（真接入）

- 只存 JWT 到 `SharedPreferences` 键 `hiko-online-token`，**刻意不进 `AppSettings`**
  —— 凭证不该出现在所有 `watch(settings)` 的构建路径上。
- **令牌失效仍返回 200**，只是 `user.loggedIn=false` → 判登录态只看字段不看状态码。
- 无 refresh、无服务端登出端点（网页登出 = `localStorage.remove("jwt-token")`）。
- 401 → 清令牌 + 提示重登，**不静默重试**；`restore()` 时网络不通**保留**令牌（断网 ≠ 令牌失效）。
- `sanitizeToken` 剥掉 `Bearer` / `__q_strn|` / 全部空白（用户给的 `__q_strn|` 前缀是复制噪声）。
- **一处自我纠错**：原注释写「带旧令牌登录会被拒」是**未验证的推断**；本轮 curl 复核发现
  `POST /api/auth/me` 带 bogus token / 不带 / JSON / form-encoded **四种形态都是同一个 401 凭据错误**
  → 已改注释，`login()` 不带 Authorization 的理由改为「跟随网页端语义」。

## 歌单收藏

- 端点：`get-playlists`（**`filterBy` 形同虚设**，all/owned/liked 都返全部）、`get-playlist-works`、
  `get-work-exist-status-in-my-playlists`（每条带 **`exist`**）、`create-playlist`（works 吃 **source_id 字符串**）/
  `edit-playlist-metadata` / `delete-playlist` / `add-works-to-playlist` / `remove-works-from-playlist`
  （后两个 **只吃数字 id**，传字符串 400 `Invalid value`）。
- playlist `id` 是 **UUID 字符串**；`privacy` 0 私享 / 1 不公开 / 2 公开；
  **系统保留歌单返回原始 key**（`__SYS_PLAYLIST_LIKED` / `MARKED`）→ 本地映射「我喜欢的」/「我标记的」，
  且禁止改名/删除。
- **角标方案推翻重做**：原计划走 `GET /api/works?withPlaylistStatus=1`，实测该字段是 **page 级**
  （整页共用一份，不是每件作品各自的），且搜索/标签端点 POST 化后**连 `pageSize` 与 `pagination` 都丢了**；
  加上 `GET /api/works` **只返回前 20 条**（`pageSize=50` 被忽略）→ 三条合起来判了这方案死刑。
  改为 `OnlineFavorites` 索引（按歌单拉全量作品）同时喂 ① 卡片角标 ② 收藏页 ③ 菜单预勾选；
  菜单打开时再用 `get-work-exist-status-in-my-playlists` 补一次**权威值**。
- **写操作模式**：先改本地内存（界面即时）→ 后台 `refresh(showLoading: false)` 校准；
  收藏发**差分**（`planPlaylistDiff`）而非全量覆盖（全量会把别处改动抹掉）。
  `appliedLocally` 空差分时返 `identical` 让 Riverpod 跳过重建。
- **不做「移动到其它歌单」**：移动 = 移除 + 加入两条请求，第二条失败就变成「从原歌单消失且没进新歌单」。
