# 2026-10-08 工作日志

## Hiko 1.99.25：修「深色下滚动时头部玻璃整块消失」

- **用户反馈**：两张 Android 截图（内容正好差 62px）+「深色模式往下划的时候上面的玻璃边框会消失」。
- **确认是真 bug，且是持久态**（不是过渡帧）：锁死在 62px 滚动位置停 30 秒，玻璃仍然不在。
- **根因**：`SliverAppBar(pinned: false)` 的 `bottomOpacity` 随滚动 < 1，Flutter 把整个
  `bottom`（= 玻璃头部）包进 `Opacity`（离屏 saveLayer）→ BackdropFilter 采不到底景 →
  描边与填充一起消失，只剩文字（文字被顺带压暗 ~7%，所以看着像「玻璃没了」）。
  Flutter 源码位置：`packages/flutter/lib/src/material/app_bar.dart:1417`（算 bottomOpacity）
  与 `:1174-1184`（`bottomOpacity == 1.0 ? bottom : Opacity(...)`）。
- **修法**：`bottom.preferredSize` 声明 `Size.fromHeight(0)`（除数为 0 → 恒 1.0 → 永不进
  Opacity），真实高度改由 `expandedHeight`/`collapsedHeight` 表达；delegate 的
  minExtent/maxExtent/extraToolbarHeight 逐值不变。三处同源抽成
  `lib/ui/widgets/hiko_floating_header.dart` 的 `HikoFloatingGlassHeader`。
- **验证**：test 679 passed / 2 skipped（+1 新锁）、analyze 42 条 0 error；
  新锁摘掉修复后第 1 档（offset=30）即红；macOS 深色实跑同滚动位置像素比对
  （文字行 dy=0 → 滚动几何零变化，玻璃描边/填充恢复）；Android AVD 实跑滚动态玻璃正常。
- **交付**：版本 `1.99.25+138`，Release `hiko-v1.99.25-macos.zip` + `hiko-v1.99.25-android.apk`。

### 复用性结论（已写进 hiko-modules.md）
- 玻璃放进任何 `Opacity` / saveLayer 里都会整块消失 —— 排查时先找有没有半透明祖先。
- **`flutter_test` 里这层 `Opacity` 是框架加的，抓得到**（与「玻璃档位在单测里看不出来」相反），
  所以这类症状可以直接写端到端回归锁。
- 一次性探针 `find.ancestor(of: find.text(…), matching: find.byType(Opacity))` 扫各滚动档的
  alpha，比截图逐像素考古可靠得多。
