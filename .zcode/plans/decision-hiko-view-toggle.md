# 决策书：全屏播放页「点唱片看歌词 / 点歌词空白回唱片」

- **日期**：2026-09-11
- **范围**：Hiko Flutter（`hiko/`），全屏播放页 `hiko/lib/ui/screens/fullscreen_player_screen.dart`
- **版本基线**：1.72.0+81
- **触发**：用户需求「在全屏播放页点击中间的唱片能够跳转歌词页面，在歌词页的空白处点击也能跳转回唱片页」
- **定稿**：四条裁决已由用户逐条拍板（见「裁决」一节）

---

## 一、问题陈述

全屏播放页中央区域在「黑胶唱片层」与「歌词层」之间二选一显示，目前**唯一**的切换入口是 AppBar 右上角那个图标按钮（`fullscreen_player_screen.dart:125-132`）。用户要求把切换手势直接落到内容上：点唱片 → 看歌词；点歌词页的空白处 → 回唱片。

这个需求看起来只是加两个手势，但实测牵出两件必须先定清楚的事（见下）。

---

## 二、实测证据

以下全部来自本机 `flutter test`（Flutter 3.47.0，手机竖屏 1080×2340 @3.0，歌词区 viewport 高 418 逻辑像素）。

### 证据 1：歌词页「空白处」无法用「下层探测器」实现

`test/ui/zz_probe_tap_test.dart` 复刻歌词页结构（`Stack` + 上下各半屏留白的 `ListView`），分别把探测器放在 ListView 下层、以及与 ListView 同层包裹：

| 探测器位置 | 点留白处 | 点歌词文字 | 拖动列表 |
| --- | --- | --- | --- |
| ListView **下层**（`Positioned.fill`） | **收不到** | **收不到** | 不触发 |
| **包裹** ListView | 触发 | 触发 | 不触发 |

结论：
- 「在下层铺一个透明手势层」这条常见做法**完全不成立**——`RenderViewport` 把落在自己范围内的命中全部吃掉，即使那一处只是 padding、没有任何子项。
- 「包裹 ListView」可以让整片区域都可点，但**文字和空白无法区分**，点歌词文字也会翻页。
- 好消息：拖动不会误触发 `onTap`（手势竞技场把拖动判给了滚动），因此不必担心滚动时误翻页。

所以「只认空白处」只有一条实现路径：**包裹一层返回手势，同时给每一行歌词加一层吸收点击的手势**——点文字被行内的吸收层拿走，点空白落到外层。这是本节要定的第一个决策点。

### 证据 2：切走再切回歌词页，当前句根本不在视口里（既有缺陷，被本需求放大）

`test/ui/zz_probe_toggle_test.dart`：播放到 100.5s（第 50 句），先进一次歌词页，再点 AppBar 按钮切到封面、切回歌词：

```
首次进歌词页: 第50句在视口内=true  offset=2174  偏差=0.0px     ← 正常
切回歌词页:   第50句在视口内=false offset=0                    ← 看到的是歌曲开头
```

根因：`_showLyrics` 为 false 时 `_buildLyricsView` 整棵子树（含那个 `ListView`）会被销毁，重进时列表从 `offset = 0` 重建；而 mixin 里「已经滚到第几句」的记账 `lastRevealedIndex` 是挂在 `State` 上的，**跨视图切换存活**。重进时 build 的闸门判定 `currentIndex == lastRevealedIndex`「已经滚过了」→ 不定位 → 停在列表顶部。

今天这个缺陷之所以没人报，是因为只有 AppBar 按钮能触发它，且下一句歌词变化时闸门会重新判定、自我修复（几秒内）。本需求把切换入口挪到「点唱片」之后，「点一下唱片，看到的却是歌曲开头」会立刻变成显眼问题——所以它属于本需求必须一并修掉的范围，而不是可选的顺手活。

### 证据 3：中央区域的尺寸关系

手机竖屏下唱片直径固定 320px，中央区高度约 418px。即「整个中央区域」≈「唱片圆盘 + 上下各约 50px 边距」，两者实际差别很小。这是第二个决策点的依据。

## 三、根因/约束归纳

| # | 事项 | 性质 |
| --- | --- | --- |
| C1 | 歌词页区分「空白处」与「歌词文字」只能靠给每行加吸收手势 | 约束（由证据 1 实测确定，无第三条路） |
| C2 | 中央区域的可点范围可松可紧，差别仅约 50px 边距 | 取舍 |
| C3 | 歌词子树切走即销毁，`lastRevealedIndex` 却跨切换存活 → 重进不定位 | 既有缺陷，本需求必须一并修 |
| C4 | 切换是瞬时硬切，点击触发时观感偏突兀 | 体验取舍 |

## 四、选项与权衡

### C1 歌词页点击范围

- **只认空白处**：点歌词文字保持现状（什么都不发生）。需要给每行加一层吸收点击的手势（约 3 行代码）。留白区（1.72.0 起上下各半屏）本身已经很大，实际好点。且**给将来「点某句歌词跳播到那一句」留了位置**——详情页歌词 tab 已经有这个能力，全屏页加上是合理演进。
- **整片区域都算**：实现最简。代价是点歌词文字也会翻页：想按住某句看内容、或想点一下让滚动停下，都会被翻回唱片页；且与将来的「点歌词行跳播」直接冲突。

### C2 唱片页点击范围

- **整个中央区域**：目标宽容，点到边缘也有反应；中央区背景是纯装饰、没有别的用途；与歌词页的「空白也能点」形成对称。
- **只认唱片圆盘**：更贴合字面，但点到圆盘外一点就没反应，容易让人以为按钮坏了。

### C3 切到歌词页时是否强制定位

- **总是定位到当前句**：不管从哪个入口进（点唱片、点 AppBar 按钮），都重新居中到当前唱的这句。同时修掉证据 2 的缺陷。而且歌词列表切走即销毁、重进必然从顶部开始，「保留上次位置」在物理上就做不到，只能二选一。
- **保留上次位置**：等于保留证据 2 的缺陷。

### C4 切换动效

- **加约 220ms 交叉淡入淡出**：点击触发的整页内容互换，且有唱片在旋转，硬切显得跳。代价：多一个 `AnimatedSwitcher`，两个子视图要能区分（加 key）。
- **保持瞬时**：改动最小。

## 五、裁决

用户逐条拍板结果：

| # | 决策点 | 裁决 |
| --- | --- | --- |
| C1 | 歌词页点击范围 | **只认空白处**（给每行加吸收点击的手势，点文字不翻页） |
| C2 | 唱片页点击范围 | **整个中央区域**（`HitTestBehavior.opaque` 铺满） |
| C3 | 切到歌词页 | **总是定位到当前句**（进入时重置滚动记账并恢复自动跟随） |
| C4 | 切换动效 | **加 220ms 交叉淡入淡出** |

### 我替领导拍的板（用户未逐条过问，按默认执行）

| 问题 | 默认值 | 猜错的代价 |
| --- | --- | --- |
| 点按是否有触觉反馈 | **有**，用 `HapticFeedback.selectionClick()`（与仓库既有习惯一致：所有可点控件都有轻反馈） | 不喜欢就去掉一行，1 分钟 |
| 三个切换入口是否共用同一段逻辑 | **共用**一个 `_setShowLyrics(bool)`，同时负责触觉、重置滚动记账、恢复自动跟随 | 散成三处会重演 1.71.0/1.71.1 那种「改一处漏一处」，返工约 1 个任务 |
| AppBar 的切换按钮 | **保留**（手势不可见，按钮是可发现性与无障碍的兜底） | 若领导要求去掉，需另议无障碍替代 |
| 是否加「可点击」的视觉提示 | **不加**（无动效提示、无箭头角标）——AppBar 按钮已承担可发现性 | 若领导要求加，属纯视觉增量 |
| 版本号 | 1.72.0+81 → **1.73.0+82**（新增用户可见交互，按 minor） | 若要走 patch，改 pubspec 一行 |

## 六、被明确否决的做法

1. **在 ListView 下层铺透明手势层来只认空白**：证据 1 实测收不到任何点击，包括留白处。此路不通。
2. **用 `onTapUp` 拿到坐标再自己判断命中了哪一行**：需要把每行的 `RenderBox` 翻出来做区间判断，代码量远大于「每行加一层吸收手势」，且随行高/字号变化容易失准。
3. **把整片区域都算作返回手势**（用户已否决）：会与将来的「点歌词行跳播」冲突。
4. **切换时保留控件可用性以外的东西**：歌词列表切走即销毁，任何「保留滚动位置」的尝试都要额外缓存 offset，而用户已裁决「总是定位到当前句」，缓存没有意义。

## 七、验收契约（供计划书引用）

- 点中央区域 → 进入歌词页；点歌词页留白 → 回唱片页；点歌词文字 → **不**回唱片页。
- 任何入口切到歌词页后，当前句必须落在歌词区垂直正中（偏差 < 16px）——含「切走再切回」这条路径。
- AppBar 图标按钮双向切换仍可用。
- 在歌词页拖动列表不会误触发翻页。
- 唱片页中央区内、唱片圆盘之外的位置（如正上方约 40px 处）点击也能切换（守住 `HitTestBehavior.opaque`）。
- 反向验证：分别去掉「每行吸收手势」「进入时重置滚动记账」「`HitTestBehavior.opaque`」，对应断言必须转红，还原后全绿。
- 基线不可退：`flutter test` 用例数不低于当前基线（262 passed / 1 skipped），skip 数不得增加。
