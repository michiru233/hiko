# Hiko macOS 端「整理当前专辑 / 重新整理音乐库」实现方案

## 1. 需求与目标
在 Hiko macOS/桌面端（以及兼容结构中），用户可能会在外部对本地音乐文件进行各种调整：
- **歌曲被删除**：源文件不存在，需要从专辑曲目中剔除；若整张专辑歌曲全部被删除，则剔除整张专辑。
- **歌曲改名 / 新增歌曲**：文件夹内新增了歌曲，或者重命名了音频文件名，需要重新发现并加入到曲目中，按 Track Number 和自然文件名自然排序。
- **元数据变动**：歌曲的 ID3/Vorbis/FLAC 标签（Title, Artist, Album, Track Number, 专辑内嵌封面, 时长等）或目录封面文件被修改，需要重新解析并更新。
- **用户状态与刮削信息保留**：在整理/重新扫描过程中，必须无缝保留用户的 `favorite`（收藏）、`played`（播放进度，安全 clamp）、`dlsiteTitle`（DLsite标题）、`tags`（DLsite 标签）、`genre`（分类）、`date`（加入时间）、`color` / `shape` 等数据。

## 2. 核心架构与模块设计

### 2.1 整理核心服务：`LibraryReorganizer` (`hiko/lib/data/library_reorganizer.dart`)
新建整理服务与结果统计模型：
- **`ReorganizeStats` 统计结果**：
  - `scannedCount`：扫描处理的专辑数
  - `updatedCount`：发生实质变动的专辑数
  - `removedAlbumsCount`：由于所有歌曲被删除而移除的专辑数
  - `tracksAdded`：新增的曲目数
  - `tracksRemoved`：剔除的曲目数
  - `tracksModified`：元数据/名称/时长更新的曲目数
- **`reorganizeAlbum(Album oldAlbum)`**：整理单张专辑。
  1. 找出专辑的有效根目录（从 `oldAlbum.sourcePath` 或曲目文件 URL 提取最长公共目录）。
  2. 若根目录不存在或无法提取，回退使用 `PlatformService.cleanMissing` 逻辑校验各曲目文件存活状态。
  3. 若根目录存在，调用扫描层解析该目录下所有音频文件及封面。
  4. 比对新旧曲目（按 URL / 相对路径比对），合并元数据。
  5. 保留用户状态（`favorite`, `played`, `tags`, `dlsiteTitle`, `genre`, `date`, `color`, `shape`）。
  6. 如果 ID3 专辑标签变更导致分组/ID 改变，妥善替换旧专辑条目，避免产生孤儿/重复。
- **`reorganizeLibrary({void Function(int current, int total)? onProgress})`**：整理全库所有专辑。
  1. 逐个目录/专辑整理，避免阻塞 UI。
  2. 统计所有增删改指标。
  3. 将更新后的专辑列表一次性或批量原子持久化到 `LibraryStore`（`replaceAll`）。

### 2.2 `LibraryNotifier` 扩展 (`hiko/lib/data/library_provider.dart`)
- 新增 `libraryReorganizerProvider`。
- 提供批量替换/更新能力，确保整理完成后 UI 状态与 `library.json` 磁盘数据完全同步。

### 2.3 偏好设置弹窗 UI (`hiko/lib/ui/widgets/settings_dialog.dart`)
- 在「数据」或「数据与失效维护」区块中新增 **「整理当前专辑」**（或「整理音乐库」）设置行与操作按钮：
  - 展示功能说明：「重新扫描库中所有专辑的音轨文件，同步歌曲增删、改名及元数据变动，并保留收藏与刮削标签。」
  - 点击后展示整理进度，整理完成后弹出浮动提示（SnackBar），详细汇报变动情况（如：`已整理 X 张专辑，更新 Y 张专辑（+A 首 / -B 首 / 变动 C 首）`）。

### 2.4 单专辑与批量操作入口（快捷整理体验）
- **专辑详情抽屉 (`DetailDrawer`)**：在「从头播放」「收藏」旁边或操作区新增「整理专辑」按钮，方便用户针对正在查看的单张专辑即时刷新。
- **专辑右键菜单 (`HomeScreen._showContextMenu`)**：在桌面端右键卡片时增加「整理专辑」选项。

## 4. 影响与边界分析
- **桌面专精**：当前严格遵循 AGENTS.md 约定，只修改 macOS/桌面端逻辑，不改动 Android 原生插件。
- **非破坏性**：用户已有的刮削结果（DLsite 标签、RJ 码、DLsite 标题）以及收藏和播放进度均受到 100% 保护。
